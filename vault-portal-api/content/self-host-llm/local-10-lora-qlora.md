决定微调了。这一篇以 LoRA/QLoRA（第 9 篇的主流档位）为对象，给一条可复制的流水线：数据 → 训练 → 监控 → 产出。工具用 Hugging Face 生态（transformers + PEFT +TRL，或 LLaMA-Factory 这类整合了全流程的开源框架——新手优先后者，把精力留给数据）。

## 第一步：数据（决定成败的 80%）

**格式**：主流是对话格式（instruction/input/output 或 messages 结构），与第 5 篇 Modelfile 的心智一致——你在用"高质量示范对话"教模型行为。

**质量标准**：

1. **一致性**：同类任务的输出风格、格式、口径完全统一——模型会忠实地学到你的不一致；
2. **覆盖度**：覆盖任务的各类分支（正常/边界/拒绝/多轮），别只喂"标准情况"；
3. **无污染**：剔除个人信息与敏感数据（数据会永久进入模型权重，比 RAG 语料泄露严重得多）；
4. **数量起点**：格式/风格类任务 500-2000 条起步；先小后大——500 条训一版看方向，比攒一万条再训科学得多。

**清洗流水线**：生产日志/文档 → 去重 → 脱敏（人名/电话/密钥）→ 格式校验 → 人工抽检 10%（抽检不过，整批回炉）。

## 第二步：LoRA 三句话原理

1. 大模型微调不必动全部权重——在原权重旁挂一对低秩矩阵（A、B），只训练这一小片；
2. 原权重冻结，可训练参数只占总量的百分之零点几，单卡可训；
3. 产物是一枚"插件"（adapter，几 MB 到几百 MB），可以插到基座模型上，也可多个插件组合切换。

**QLoRA** = 在 4bit 量化的基座上做 LoRA——训练显存再降一档，让单张 24G 卡能微调 30B+ 级模型（第 2/7 篇的量化思想在训练侧的复用）。

## 第三步：训练配置的关键参数

用 LLaMA-Factory 这类框架时，真正需要理解并调的参数：

| 参数 | 含义 | 起步建议 |
| --- | --- | --- |
| learning rate | 学习步幅 | LoRA 典型 1e-4 ~ 2e-4，过大学崩、过小学不动 |
| epochs | 全量数据过几遍 | 1-3 起步；loss 不降再加，别默认开大 |
| lora rank (r) | 插件容量 | 8-32 起步；任务越复杂越大 |
| batch size(有效) | 每步样本数 | 显存不够用梯度累积凑等效值 |
| max length | 训练样本截断长度 | 覆盖你的样本长度上限 |

**数据切分**：留 5-10% 做验证集——训练过程只看验证 loss 判断方向，绝不看训练 loss（它只会降）。

## 第四步：训练中的监控与止损

盯三条曲线：

- **验证 loss 应下降后趋平**：还在降 → 可以多训；开始回升 → 过拟合，回退到最优检查点；
- **训练 loss vs 验证 loss 的缺口**：缺口快速拉大 = 在背题，不是在学——减 epochs 或加数据；
- **灾难性信号**：输出变成乱码/复读/语言切换——学习率过大或数据格式错，立即停。

全程存检查点（checkpoint），训练过程可中断可续跑；配置文件进 git（第 12 篇 Agent 库同款纪律：可复现是底线）。

## 第五步：产出与验收

训练产物 = LoRA 插件。验收流程（第 11 篇展开）：合并或挂载插件 → 与基座模型跑同一评测集对比 → 通过后走第 7 篇的量化 → 第 6 篇的服务发布。

**常见翻车清单**：数据格式与模板不匹配（训练时用什么对话模板，推理时必须一致）；忘记训"拒绝样本"（模型学成了有求必应）；数据里混入测试集样本（评测虚高）。

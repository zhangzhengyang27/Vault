Agent 演示阶段账单几十块，上生产变成每天几千——这不是夸张，是多步循环的自然放大：单次任务 30 步 × 每步数万 token，再乘并发。这一篇讲怎么把成本与延迟管进预算，以及怎么算清"一个任务值多少钱"。

## 先算账：单位经济学

上线前算三笔账，用评测集的真实轨迹（第 6 篇）而非拍脑袋：

1. **单任务成本** = Σ(每步输入 token × 单价 + 输出 token × 单价) + 工具外部调用费。注意输入 token 占大头（上下文里全是历史），这正是第 10 篇压缩的直接动机；
2. **失败成本**：完成率 70% 意味着真实单任务成本 ÷ 0.7——失败重试也是钱；
3. **人机成本**：人工确认、人工接手的操作成本，往往比 token 贵。

三笔账得出"单任务全成本"，对照它创造的价值（省下的人力/提升的转化），**值不值的问题才有答案**。很多 Agent 项目的结论是"暂时不值"，这本身就是有价值的结论。

## 四个成本杠杆（按性价比排序）

**1. 模型分级。** 不是每一步都需要旗舰模型：路由/改写/摘要用小模型，规划与关键决策用旗舰。分级的前提是任务结构清晰（第 1 篇工作流化）——结构越清晰，分级空间越大。常见实现：简单节点 3-5 倍价差，整体成本砍半是常态。

**2. 缓存。** 三层：模型侧前缀缓存（系统提示词+固定前缀命中缓存价）；结果缓存（相同工具调用+参数直接返回，相同任务直接复用产物）；语义缓存（相似问题复用答案，谨慎用）。高频场景的缓存命中率直接改写成本曲线。

**3. 上下文压缩。** 第 10 篇的工程在这里兑现成钱：摘要替代全量历史、引用替代大产物、检索替代常驻。输入 token 减半 = 接近减半的成本。

**4. 步数控制。** 死循环与过度检索是成本黑洞（第 7 篇观测抓它）：步数上限、提前完成判定（"证据已足够，停止检索"）、任务拆小（每步更聚焦）。

## 延迟：分层优化

用户感知的延迟 = 首响应时间 + 总完成时间，两者分开优化：

- **首字时间**：流式输出（必开）；先给"计划"再执行（"我会先检索 A，再对比 B…"）——用户看到进展，容忍度立刻不同；
- **并行化**：无依赖的工具调用并行发（第 2 篇计划里的独立步骤）、子任务并行（第 5 篇）；
- **降级路径**：给每层设延迟预算，超时降级（跳过重排用 RRF 序、切换快模型）；
- **预取**：高概率会用的数据在用户输入时就预取（如输入中出现客户名即拉档案）。

## 预算控制：给每个 run 上闸

生产 Agent 必须有硬预算：单 run token/费用上限、步数上限、外部调用上限、墙钟时间上限。到闸的处理分级：保存进展请求增购（转人工确认继续）、降级到轻量路径、干净失败（第 8 篇）。**预算闸是成本失控的最后一道保险**——提示词说"请节约使用"没有任何约束力。

## 一个反直觉的建议

优化顺序别搞反：**先看完成率，再看成本**。完成率 60% 的系统优化成本，是把"无效产出的钱"省下来，但商业价值归零；先把完成率做到 90%+，再收成本杠杆，单位有效成本才是真实指标。所有优化动作都要过第 6 篇评测集回归——省了钱砸了质量，是成本优化最常见的翻车姿势。

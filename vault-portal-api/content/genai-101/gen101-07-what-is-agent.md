到目前为止你看到的 AI 都是"一问一答"。但很多时候我们的需求不是"一个答案"，而是"办成一件事"：订好出差的机票酒店、把 100 份简历筛完、盯一个数据看板发现问题就报告。**AI Agent（智能体）**就是为此而生的形态：给它目标，它自己拆步骤、调工具、看结果、再修正。

## Agent 与聊天机器人的本质区别

| 维度 | 普通对话 | Agent |
| --- | --- | --- |
| 交互 | 一问一答 | 给目标，多步自主执行 |
| 能力 | 只会说话 | 会调用工具（搜索、点按钮、写数据库、跑代码） |
| 记忆 | 对话内记忆 | 可跨会话积累状态与知识 |
| 纠错 | 你指出它改 | 自己看执行结果，失败就换路子重试 |

一个直观例子：你说"帮我调研这三家竞品的定价，整理成对比表"。普通对话只能基于它背过的旧知识聊聊；Agent 会真的去打开网页、逐家抓取定价页、发现某家信息缺失就换关键词再搜，最后把结果写进表格。**它执行了动作，而不只是输出了文字。**

## 四个核心零件

1. **规划**：把大目标拆成小步骤。"调研竞品"被拆成"确定三家名单→逐家检索→抓取定价页→汇总"。
2. **工具**：模型本身只会生成文字；"手脚"来自工具——搜索 API、浏览器操作、代码执行、文件读写。工具定义得越清晰，Agent 用得越好。
3. **记忆**：短期记忆是对话上下文；长期记忆靠外部存储（比如把重要结论写进数据库，下次先查再干）。
4. **反思与重试**：拿到工具返回的结果后，检查是否达成目标，失败时分析原因换方法。这是 Agent 区别于"固定脚本"的关键。

## 它为什么现在才火

模型变强（能可靠地多步推理）、工具协议标准化（MCP 让"给 AI 接工具"从定制开发变成标准插头，见本站 MCP 知识库）、成本下降——三者叠加，Agent 从演示变成了产品。2025-2026 年的编码 Agent、深度研究、计算机操作类产品都是这波浪潮的产物。

## 什么时候该用 Agent

**适合**：多步骤、有明确完成标准、每步可验证、重复性高的任务——批量信息处理、定时监控、跨系统搬运数据、代码修改与测试。

**不适合**：一步就能答完的问题（直接问就好）、需要人类担责的决策（Agent 只做草稿）、高 stakes 且无法验证输出的场景。

## 一条务实的安全线

Agent 拥有的每一样"手脚"都是权限。让 Agent 帮你发邮件，它就能发错邮件；让它操作银行，风险自明。**给最小必要权限、重要动作加人工确认**，是使用一切 Agent 产品的第一原则。

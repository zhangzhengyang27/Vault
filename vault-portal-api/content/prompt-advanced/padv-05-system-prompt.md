产品化 AI 的系统提示词（System Prompt）不是一句话人设，而是一份几百到几千字的"员工手册"：身份、规则、流程、输出规范、禁止事项。它的问题从来不是"写不出"，而是**越写越长、越改越乱、没人说得清哪句在起作用**。这一篇讲组织与维护。

## 分区骨架：一份可复用的模板

```markdown
# 角色
你是 XX 产品助手，服务对象是…，你的使命是…

# 核心规则（3-5 条，违反即事故的）
1. 仅依据提供的资料回答，不足时明确说明
2. 涉及金额/法律/医疗的请求必须提示咨询专业人士
3. …

# 输出规范
- 语言与格式要求、长度基准、引用格式

# 流程指引（按任务类型分节）
## 处理退款咨询时：先…再…
## 处理投诉时：…

# 边界与禁止
不做什么、遇到 XX 转人工、语气红线

# 当前上下文
{变量区：用户信息/检索结果/时间等}
```

要点：**最重要的规则放最前**（注意力稀释规律，Agent 库第 10 篇）；每区内容少而硬；"流程指引"按任务类型分节而不是写成一大段——模型按输入匹配到对应节，遵循率远高于混杂长文。

## 优先级冲突：预案要先写

规则一多必然打架（"简洁回答" vs "完整解释条款"）。与其指望模型临场权衡，不如显式写优先级："安全 > 合规 > 正确性 > 简洁"。冲突预案是系统提示词里最被低估的部分——**你能在评审室里想到的冲突，就该在文档里替模型想好**。

## 分工：系统提示词不是垃圾桶

四类内容各有更合适的家，别全塞进系统提示词：

| 内容 | 更好的位置 |
| --- | --- |
| 工具使用时机与禁忌 | 工具描述本身（MCP 库第 3 篇）——模型看工具时才需要 |
| 硬约束（禁止删除/外发） | 护栏代码（Agent 库第 8 篇）——提示词只是锦上添花 |
| 知识性内容 | RAG 检索（本地部署库第 9 篇）——不要把手册全文贴进系统区 |
| 动态信息（日期/用户数据） | 变量注入区——别写死，也别让模型"猜" |

判断口诀：**稳定的行为规范进系统提示词，其他各回各家。**

## 膨胀治理

系统提示词会自然增肥：每次出问题就加一条规则，半年后它变成几千字、自己就是最大的成本项与注意力干扰源。治理三板斧：

1. **定期瘦身**：每条规则问"它阻止过什么事故？"——答不出且有护栏/流程兜底的，删；
2. **合并同类**：十句零散的"语气要求"合并成一段语气总纲；
3. **外迁**：任务专属的长流程指令下沉为 Prompt 模板（MCP 库第 4 篇）或任务型提示词，系统区只留"永久人格与全局规则"。

## 维护纪律

系统提示词是全系统影响面最大的文本——**它的一次修改等于一次代码发布**：

- 进版本管理，改动有 commit 与评审；
- 每次修改跑评测回归（第 7 篇）；
- 大改用"灰度提示词"：新旧两版分流量对比（第 8 篇）；
- 文档化"为什么"：每条规则旁注一句来历（哪次事故/哪个需求），半年后的维护者会感谢现在的人。

## 一个自检方法

把系统提示词交给一个没接触过项目的人（或另一个模型）读，问三个问题：这个助手该做什么？什么绝对不做？遇到 X 情况该怎么处理？**答不上来的部分，就是写得不清的部分**——模型的理解力并不比这个人强多少。

提示词工程的多数教程停在纯文本对话。但生产系统里，模型越来越多地"看图办事"（识别、审单、截图分析）和"调用工具"（Function Calling/MCP）。这两类场景的提示词有自己的规律，这一篇补齐。

## 图像理解：把"看"变成"查"

多模态模型看图的能力很强，但**你问什么决定它看什么**。要点：

1. **明确提取目标与输出结构**："找出图中所有金额并列表"远好于"看看这张图"——视觉注意力是按任务调焦的（与结构化输出第 3 篇同理：字段越明确，提取越稳）；
2. **告知图像类型与视角**："这是一张手机拍摄的 PDF 页面，可能有反光/倾斜"——给模型预期，减少它对噪点的误读；
3. **承认视觉不确定性**：对手写体、低分辨率区域，提示词里给台阶："无法确认的字段标注 uncertain，不要猜测"——把幻觉出口堵在指令层；
4. **关键决策要求双重校验**：先描述看到了什么，再下结论——两段式输出让"看错"与"判错"可分离定位（CoT 第 2 篇在视觉上的应用）。

高频坑位提醒：表格图片转数据（行列错位是重灾区，要求按单元格逐行输出）、含文字的截图（要求逐字转录而非"概括"）、多图对比（显式编号"图1/图2"）。

## 工具调用场景：指令是"使用说明书"

模型决定调不调工具，依据是工具描述 + 你的任务指令（MCP 库第 3 篇讲过工具侧）。任务侧的提示词要点：

1. **说明可用工具的分工**：当工具多时，任务指令里主动引导——"查订单状态用 order_query，不要用 search 猜"——比指望模型在 15 个工具里自己分清可靠得多；
2. **规定调用纪律**：最多调用几次、什么情况必须先问用户、哪些工具的结果需要交叉验证（Agent 库第 2 篇的预算思想在提示词层）；
3. **结果融合的格式**：多工具结果怎么合成最终回答（"逐工具列出发现，再统一结论"）——不说清，模型会偏心某一个来源；
4. **失败路径**："工具报错时告知用户并停止，不要编造工具返回的内容"——把"幻觉工具结果"这个高危模式显式禁止。

## 语音与实时场景

语音对话（ASR→模型→TTS）的提示词差异：

- **为耳朵写**：短句、不用列表符号与 Markdown（读出来是灾难）、重要信息重复一次；
- **处理转写噪音**：语音识别的错误输入要设计容错指令（"如果用户表述含糊，确认后再行动"）；
- **回合感**：指令模型保持单轮聚焦，别输出长篇——语音场景的"简洁"不是风格是刚需。

## Agent 场景的提示词分工

Agent 系统里提示词散布在多层（Agent 库第 1-3 篇），避免重复与冲突的原则：

- **系统提示词**管身份、全局规则、优先级（第 5 篇）；
- **工具描述**管"这个工具何时用"；
- **任务指令**管"这一件事怎么做"；
- 三层说同一件事但措辞冲突时，模型行为不可预测——**升级一层的内容，下层就删**（Agent 库第 10 篇的上下文预算同样适用）。

## 小结

多模态提示词的核心是把"看/听/调"变成有明确提取目标与输出结构的任务；工具场景的核心是分工说明、调用纪律与失败路径。下一篇是全库收官：一份按"症状→病因→修法"组织的反模式清单，供你平时对症自查。

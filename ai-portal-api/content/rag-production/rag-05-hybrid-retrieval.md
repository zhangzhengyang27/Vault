很多团队做过一次经典实验：把同一个问题分别用向量检索和关键词检索跑一遍，发现两者"各自都能找到对方找不到的答案"。结论：**它们不是替代关系，是互补关系**。混合检索（Hybrid Search）由此成为生产级 RAG 的标配。

## 向量检索的三类失效

1. **精确标识符**：型号"XR-450B"、错误码"E_1024"、法条编号——向量会把它们"语义化"后丢失精确性，反而搜不准。
2. **罕见词与专有名词**：人名、产品代号、行业黑话在训练语料中出现极少，向量表达不可靠。
3. **否定与细粒度区别**："不含防腐剂"和"含防腐剂"的向量可能非常接近，但意思相反。

## BM25 的互补价值

BM25 是经典的关键词打分算法（TF-IDF 的改进版）：词频 + 逆文档频率 + 文档长度归一。它恰好补向量短板——精确词匹配极强，你搜"XR-450B"它就给你含"XR-450B"的段落。反过来它又缺向量的同义改写能力（"报销"搜不到"费用申请"）。

两路并行，各取所长：

```
查询 ──┬── 向量检索 → 候选 A
       └── BM25 检索 → 候选 B
                ↓
           RRF 融合排序 → Top-K
```

**RRF（Reciprocal Rank Fusion）**是标准的融合方法：每个文档的得分 = Σ 1/(k + rank)，即"在各路结果里的名次越靠前，融合分越高"。它不依赖两路分数的可比性（向量余弦分和 BM25 分不同纲），实现十行代码，效果稳健，几乎是默认选择。

## 多路召回不止两路

思路可以继续扩展：向量库按不同 embedding 模型各建一路、按文档标题/摘要单独建一路、结构化字段过滤一路（日期、类型）。多路召回的价值在"覆盖不同失败模式"，代价是延迟与算力——生产中通常 2-3 路，按评测集验证每一路的边际贡献。

## Top-K 与评估

- **Top-K 取多少**：K 太小漏证据，太大塞爆上下文且引入噪音。常见起点 K=8~20（进重排前），重排后压缩到 3-8 进上下文（第 7 篇）。
- **检索评估看什么**：核心指标是**命中率**（正确出处是否进 Top-K）与 MRR（正确出处排多前）。评测集建法见第 9 篇。
- **归因要分开测**：把"检索命中率"和"回答质量"分开评估，出问题时才能定位是"没找到"还是"没答好"——这是 RAG 排查的基本功（第 10 篇）。

## 小结

- 默认上混合检索：向量 + BM25 + RRF 融合；
- 精确标识符、专有名词多的语料，BM25 一路的权重值得加大；
- K 值、路数用评测集定，别拍脑袋。

## 它是什么

[Common Crawl](https://commoncrawl.org/) 是一家非营利基金会（2007 年起），用爬虫按月抓取全网公开页面，把原始档案（WARC 格式）与提取文本（WET）、元数据（WAT）免费开放在 AWS S3 上。单次月度抓取约 20 亿+ 网页，累计档案已达 PB 级。

它与大模型的关系：**估计 70–90% 的 LLM 训练 token 追根溯源来自 Common Crawl**（该基金会自己在版权咨询中的说法）。FineWeb、Dolma、RedPajama、C4……几乎所有主流开放语料都是对 Common Crawl 原始档案清洗、过滤、去重后的产物。

## 为什么你几乎不会"直接用"它

原始爬虫档案的问题：
1. **噪声极高**：垃圾站、模板页、乱码、重复内容占比很大；
2. **工程门槛**：PB 级数据分布在数万个小文件里，处理需要分布式管线（Spark/Ray 级别）；
3. **质量信号缺失**：原始档案不告诉你哪部分文本"值得学"。

所以实际的使用姿势是：**把 Common Crawl 当"水源"，从它的衍生数据集取水**——FineWeb 系（高质量网页文本）、RedPajama-V2（带质量信号的原始池）等，详见下一篇《开放预训练语料全景》。

## 直接使用的正确姿势

确需原始档案时（研究去重算法、自建清洗管线、训练数据溯源）：

- **Index Server**：Common Crawl 提供列式索引（CDX/Columnar），可按 URL 查到某页面出现在哪次抓取的哪个文件，避免全量扫描；
- **按快照下载**：每次抓取（snapshot）有编号，衍生数据集通常会标注用了哪些快照，便于对齐；
- ** Athena/Spark**：官方教程基于 AWS Athena 与 Spark 示例，按列读取 WAT/WET 元数据。

## 版权争议：绕不开的话题

Common Crawl 正处于 AI 版权风暴的中心：
- 2025 年的调查报道指出，部分**付费墙内容**通过伪装 UA 的抓取混入了档案，出版商与新闻机构的维权压力持续加大；
- 越来越多网站通过 robots.txt 或屏蔽手段拒绝被抓取，未来档案的覆盖面与"干净程度"存在不确定性；
- 应对这一趋势，社区出现了以"许可安全"为卖点的替代语料（Common Pile、Common Corpus，见下一篇）。

对使用者的含义：**基于 Common Crawl 的数据在商用场景存在合规灰区**，严肃商用要么选择带许可说明的语料，要么准备自己的版权审计。

## 速记

- 是什么：月度全网抓取的公益档案，LLM 语料的共同上游
- 直接用：难（PB 级、高噪声），走衍生数据集
- 什么时候碰原始档案：数据管线研究、溯源审计
- 风险点：版权争议持续发酵，商用注意许可链

十二篇的零件都齐了。收官这一篇把它们组装起来：三种典型角色各拿一条现成路线，照单实施即可。

## 路线一：个人玩家（预算：一张消费级显卡/Mac）

**目标**：本地跑通日常使用，数据不出自己的电脑。

```
Ollama(第5篇) + Qwen 14-32B 4bit(第2/3篇) + OpenAI兼容端点接桌面工具
```

- 十分钟起步（第 5 篇），显存对照第 2 篇的表；
- 进阶两步：换更大量化杯（第 7 篇）、给常用角色写 Modelfile；
- 到此为止就很好——个人场景不需要 vLLM，更不需要微调。

## 路线二：团队知识库（预算：1-2 张数据中心卡）

**目标**：团队内部的"问答 + 知识检索"服务，数据不出公司。

```
vLLM 服务(第6篇) + RAG 管道(本站RAG库) + 网关鉴权限流(第8篇) + 评测集
```

- 模型：32B 级量化（第 2/7 篇），按团队并发压测定配置（第 6 篇）；
- 知识接入走 RAG——**先 RAG 后微调**（第 9 篇分工），大概率 RAG 就够了；
- 评测集建在上线前（第 9 篇），bad case 每周运营；
- 运维按第 8 篇清单跑顺，这个服务可以撑很久。

**升级信号**：格式/风格类需求提示词管不住、或要把服务从旗舰 API 迁到本地省钱——那时启动微调线（9-11 篇），用生产日志造数据。

## 路线三：企业私有化（预算：多卡集群 + 运维人力）

**目标**：全公司级 AI 基础设施，数据与成本双可控。

```
混合路由(第1篇) + 多实例 vLLM 集群(第6/8篇) + 分场景微调模型(9-11篇) + MCP 工具层(本站MCP库)
```

- **按数据敏感度路由**：公开任务走云 API 旗舰，敏感任务走本地；应用层全部走 OpenAI 兼容接口，路由在网关层做；
- **按场景拆模型**：客服微调版、代码微调版、通用问答版——第 11 篇的三方对比表决定每个场景用哪个；
- **工具层标准化**：内部系统的 MCP 化（第 10 篇场景三的方法），Agent 能力接通全公司系统；
- **治理**：监控审计（第 8 篇）、发布纪律（第 12 篇 Agent 库）、安全红线（第 9 篇）三位一体。

## 三条路线的共同心法

1. **先验证再投入**：任何路线都从"小杯模型 + 真实任务盲测"开始，评测集是你最便宜的导航仪；
2. **标准接口留后路**：一切服务用 OpenAI 兼容层暴露，未来换模型/换引擎/混合路由都不伤应用层；
3. **知识走 RAG、行为走微调、风格先试提示词**——这条分工线记牢，能省下最多的冤枉钱；
4. **锁版本、可回滚、评测门禁**——所有"发布"（模型/配置/数据）一个纪律。

## 与本站其他知识库的联动

- 检索管道的深度实现 →《RAG 从入门到生产》
- 在本地模型上跑 Agent 与工具 →《MCP 从零到一》《智能体原理与生产化》
- 本地模型的提示词适配 →《提示词工程进阶》
- 追踪新模型与评测方法 →《AI 数据库与数据源》

十二篇完结。本地部署与微调的门槛在这两年下降了一个数量级——门槛已经不是技术，而是"想清楚要不要、在哪一档投入"。希望这张地图帮你在正确的档位上开始。

"要不要把模型搬到自己机器上"是每个团队在 AI 化过程中都会遇到的问题。答案取决于你要什么：本地部署买到的是**控制权**，付出的是**运维责任**。这一篇帮你判断自己属于哪种情况。

## 本地部署真正买到什么

按价值排序：

1. **数据不出域**：敏感数据（客户资料、内部文档、代码）不经过第三方服务器——这是合规与保密的硬需求，也是私有化部署的第一动机；
2. **成本可预测**：API 按量计费在高用量下可能失控；自有硬件边际成本趋近于零（但见下文"真实成本"）；
3. **不依赖服务可用性**：API 限流、涨价、区域下线、政策变化——自建不受制于人；
4. **深度定制**：微调、改系统层、控生成参数的完全自由；
5. **离线可用**：内网、边端、无外网环境唯一的选择。

## 不适合本地部署的信号

- **用量小**：每天几百次调用，API 月费几百块——买卡、租 GPU、运维的心智成本远超它；
- **追最强模型**：旗舰闭源模型的能力领先是常态，本地开源模型总是"上一代水平"（但差距在缩小，且很多任务用不到旗舰能力）；
- **没有运维人力**：GPU 驱动、显存碎片、推理服务升级、安全补丁——没有能接住这些的人，自建等于把稳定性押给运气；
- **需求是"偶尔用一下"**。

## 真实成本构成（别只算电费）

| 成本项 | 说明 |
| --- | --- |
| 硬件/租用 | 显卡购买（一次性大额）或 GPU 云租用（按卡时） |
| 运维人力 | 部署、升级、故障处理——常被漏算的大头 |
| 工程适配 | 接入鉴权、监控、与业务系统集成 |
| 效率损失 | 同等质量下自建模型的 token 效率可能低于旗舰 API |
| 机会成本 | 团队时间花在基础设施而非业务 |

云 API 与自建的对比，应该用**同等产出质量下的总成本**来算，而不是单纯比单价。

## 三条路线

1. **纯 API**：起步默认路线，什么都能用，什么都不用管；
2. **纯自建**：数据敏感或用量巨大（月 API 账单已够付 GPU 租金）时成立；
3. **混合路线（多数团队的终态）**：通用任务走云 API，敏感数据/高频任务走本地部署；架构上做好抽象（OpenAI 兼容接口是事实标准），任务按数据敏感度与成本路由。本库第 12 篇展开这条路线。

## 一个务实的判断流程

1. 数据是否敏感到不能出域？是 → 自建（或找合规 API 通道）；
2. 月 API 账单是否已超过"租卡+运维"的估算？是 → 认真评估自建；
3. 是否需要深度定制（微调/特殊部署形态）？是 → 本库第 9-11 篇；
4. 以上都不是 → 继续 API，把精力花在应用层。
